GTM Deal Pipeline · in-app pipeline · 3 agents

Three agents, three gates, two ways out

A deal enters as free text and leaves either qualified — with a tier, a fit level and a module breakdown — or dropped with the gate that stopped it. Each stage is one agent returning JSON against a schema, and each can be run standalone from the CLI.

One agent per stage

Runnable standalone

  • scoring_agent.py — BANTi (5×20) + F³ (3×5)
  • discovery_agent.py — fit level per requirement
  • solution_shaping_agent.py — modules, functions, risk
  • Each returns JSON against a schema in its prompt — no free-form text accepted

Gate arithmetic

What each gate tests

  • 1 · Scoring — Go if BANTi ≥ 60 / 100
  • 2 · Discovery — Full Fit < 20% custom · Partial Fit 20–50% · Full Custom > 50% (all-custom ⇒ No Fit)
  • 3 · Shaping — Go if solution_fit ≥ 3 and feasibility ≥ 3; No-Go if customization_ratio > 60%

Tier ladder · from F³

How the deal gets sold

  • Tier 1 · F³ < 8 → template proposal
  • Tier 2 · F³ 8–11 → story-driven proposal
  • Tier 3 · F³ 12–15 → strategic C-level consulting
